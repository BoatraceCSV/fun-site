# ボートレース ドメイン知識

fun-site が予想ロジックの土台にしているボートレース固有の知識をまとめる。

## 1. レース展開予想に使うデータと優先度

### 必須（朝の初回ビルドから利用可能）

データソース: BoatraceCSV `programs/title` + `programs/race_cards`

- `programs/title`: レース名・グレード・締切時刻などのメタ情報
- `programs/race_cards`: 選手・モーター・成績の出走表本体

| データ項目 | 説明 | BoatraceCSV カラム |
|---|---|---|
| 枠番（艇番） | 1〜6 号艇。枠番＝コースとほぼ一致（1 号艇の 1 コース取得率 ~98%） | `艇番` |
| 選手級別 | A1, A2, B1, B2 の 4 段階 | `級別` |
| 全国勝率 | 選手の全国勝率 | `全国勝率` |
| 全国2連対率 | 選手の全国2連対率 | `全国2連対率` |
| 当地勝率 | 当該競艇場での勝率 | `当地勝率` |
| 当地2連対率 | 当該競艇場での2連対率 | `当地2連対率` |
| モーター2連対率 | 現在のモーターの成績 | `モーター2連対率` |
| ボート2連対率 | 現在のボートの成績 | `ボート2連対率` |
| 選手体重 | 軽い方が有利（特にモーニング・ナイター） | `体重` |
| 今節成績 | 節間の調子（最大 6 レース分） | `今節成績1`〜`今節成績6` |
| 全国平均ST | 選手の全国平均スタートタイミング | `全国平均ST` |

### AI 総合評価

データソース: BoatraceCSV `estimate/index`

予想者の `componentKeys` に応じた要素（例: 本命予想は 枠番 / 選手 / モーター / 展示 / 気象)の
寄与pt を合計したものが「強さpt」。コース予想 (v6_course、2026-08-09 退役) は枠番の代わりに
**コース**要素（場×レース番号×コース別強度、`N枠_寄与_コースpt`)を使う。

| データ項目 | 説明 | BoatraceCSV カラム |
|---|---|---|
| 状態 | `daily`（直前情報未取得時）/ `realtime`（直前情報反映後） | `状態` |
| 枠番 pt 寄与 | 枠番要素の寄与スコア | `N枠_寄与_枠番pt` |
| コース pt 寄与 | 場×レース番号別コース強度の寄与スコア（v6_course / v7_aggregate / v8_aionly。枠番の代替。3 者とも 2026-08-09 退役のため現行 active には無い） | `N枠_寄与_コースpt` |
| 選手 pt 寄与 | 選手要素の寄与スコア | `N枠_寄与_選手pt` |
| モーター pt 寄与 | モーター要素の寄与スコア | `N枠_寄与_モーターpt` |
| 展示 pt 寄与 | 展示要素の寄与スコア（state=daily では暫定値） | `N枠_寄与_展示pt` |
| 気象 pt 寄与 | 気象要素の寄与スコア（state=daily では暫定値） | `N枠_寄与_気象pt` |
| 強さpt | 採用要素の寄与合計 | `N枠_強さpt` |

寄与に加えて**成分pt そのもの**（偏差値スケール 50±10、`N枠_{label}`）も
`AiEvaluationEntry.components` として取り込む。`寄与 = 場別重み × 成分pt` の関係にあり、
選手pt の内訳ページ・モーターpt の詳細ページが偏差値を直接表示するのに使う。

`state=daily` のレースでは展示・気象が暫定値（寄与 0）なので、UI 側で展示・気象セグメントを除外し 3 要素のみ表示する。

#### 選手pt の計算

選手pt だけは**素点（算出基準点）を fun-site 側で再計算できる**。入力の近況5節
（`programs/recent_national` / `recent_local`）を `RacePrediction.recentForm` として
持っているためで、計算過程は
[選手詳細ページ](web.md#ページ)で開示する。実装は
[`packages/shared/src/utils/racer-pt.ts`](../packages/shared/src/utils/racer-pt.ts)
（BoatraceCSV `scripts/boatrace/index_features.py` の `racer_pt_for_boat()` の移植）。

1. **素点** = Σ 着順スコア ÷ 出走回数。着順スコアは グレード分類（SG/GⅠ・GⅡ・GⅢ一般）×
   優勝戦か × 着順 1-6 の表引き。**F / L / 失 / 妨**（選手責任）は 0 点だが出走回数に計上し、
   **欠 / 転 / 落 / 沈 / エ / 不**（選手責任外）は分子・分母とも計上しない
2. **選手pt** = 50 + 10 × (素点 − μ_場) ÷ σ_場。μ / σ は場別・月次で学習された値で
   fun-site には取り込んでいないため、この値は index CSV から読む
3. **寄与** = 場別重み × 選手pt

移植で合わせておく必要がある BoatraceCSV 側の挙動:

- 丸めは Python の `round()` に合わせた**偶数丸め**（`Math.round` では 56.5 のようなケースで 1pt ずれる）
- `[F]` `[妨]` のように**優勝戦の括弧に着順以外が入る**ケースは、括弧内から着順の数字だけを
  拾う実装のため得点にも出走回数にも計上されない（bare な `F` とは扱いが違う）
- 全国5節と当地5節は重複排除せずに連結されるため、**当地で走った節は 2 回計上**される
- 素点が計算できない（近5節に有効な出走履歴が無い）場合、選手pt は平均の 50 ではなく
  **30** で補完される（`COMPONENT_MISSING_FALLBACK`）
- 選手pt は preview 由来ではないので、`daily` 行と `realtime` 行で値は変わらない

#### モーターpt の計算

モーターpt は選手pt と違い、**素点を fun-site 側で再計算できない**。入力が
「当場の過去6節ぶんの `race_cards`（全モーターの全走）」と「コース補正のための
全24場横断ベースライン」で、fun-site は当日ぶんの CSV しか取得していないため。
[モーター詳細ページ](web.md#ページ)は BoatraceCSV が出した値をそのまま表示し、
**何を測っている数字なのか**（スコア表・トークンの扱い・3つの補正）を開示する。
スコア表と採点ルールの移植は
[`packages/shared/src/utils/motor-pt.ts`](../packages/shared/src/utils/motor-pt.ts)
（BoatraceCSV `index_features.py` の `score_motor_run()` 等）。
設計は BoatraceCSV `docs/design/motor_ability_index_v2.md`。

1. **素点** = 直近6節の走を 級別 × グレード分類 × 着順 のスコア表で採点し、
   時間減衰（半減期60日）・コース補正（級別×グレード×進入コースの z 残差）・
   ベイズ収縮（k=10）をかけた加重平均。**当日を含む節は対象外**
2. **モーターpt** = 50 + 10 × (素点 − μ_場) ÷ σ_場
3. **寄与** = 場別重み × モーターpt

選手pt との違いで押さえておくところ:

- スコア表は**上位級ほど点が低い**（同じ1着でも B2=125pt / A1 の一般戦=50pt）。
  測りたいのは選手ではなくモーターの出来なので、上位級の好走は割り引く。
  B1・B2 は開催グレードで分けない（グレード分類「全」の 1 行）
- **F / L / 失 / 妨 / 欠 / 不 は集計から外す**（選手pt では F・L を 0 点で出走回数に
  計上し素点を強く下げる。フライングはモーターの出来ではないため扱いが逆）。
  機材起因の **転 / 落 / 沈 / エ は -100 点**で打点に計上する
- 節の検出は当場の開催日を最大90日遡って行い、**モーター期の起算日より前の節は除外**する
- 有効な走が無いモーターの素点は欠損になり、モーターpt は 50 で補完される
  （選手pt の 30 補完とは違い `COMPONENT_MISSING_FALLBACK` の既定値）
- 出走表のモーター2連率・3連率や `motorStats` の期成績は**モーターpt の入力ではない**。
  別系統の指標なので、モーター詳細ページでは並べて出しつつその旨を明記する
- モーターpt は preview 由来ではないので、`daily` 行と `realtime` 行で値は変わらない

`computeMotorSessionBreakdown()` が返すのは**今節**の走をスコア表で採点した参考値で、
モーターpt には入っていない（当日を含む節が対象外のため）。時間減衰・コース補正・
ベイズ収縮もかけない単純平均で、「このモーターが今節どう走っているか」を
モーターpt と同じものさしで読むためだけに出す。

### 直前情報

データソース: BoatraceCSV `previews/stt`（締切 5 分前以降に順次公開）

| データ項目 | 説明 | 備考 |
|---|---|---|
| 進入コース | 実際のコース取り（枠なり or 前付け） | 枠番と異なる場合がある |
| スタート展示 | 試走でのスタートタイミング | 実際のスタート力の指標 |

未取得のレースは進入コース＝枠番、スタートタイミング＝全国平均ST にフォールバックする。

### レース結果

データソース: BoatraceCSV `results/realtime`（当日確定直後に追記）

| データ項目 | 説明 |
|---|---|
| 着順 | 1〜6 着 |
| 決まり手 | 逃げ / 差し / まくり / まくり差し / 抜き / 恵まれ |
| ST | 各艇の実測スタートタイミング |
| 天候・風向・風速・波高 | 着順と並んで配信 |

K-file 由来の翌日確定 `results/daily` は本サイトでは使わない。

### 払戻金

データソース: BoatraceCSV `results/payouts`（当日確定直後に追記）

| データ項目 | 説明 |
|---|---|
| 単勝 / 複勝 | 1着艇 / 上位 2-3 着艇の払戻金 |
| 2連単 / 2連複 | 組番・払戻金・人気 |
| 拡連複 (3スロット固定) | 1-2着 / 1-3着 / 2-3着 の各ペア。販売されないレースは null |
| 3連単 / 3連複 | 組番・払戻金・人気 |

`results/realtime` (着順) と独立に追記される。**3連単 戦略の的中率・回収率算定**に使う。

### 的中率・回収率の母数

的中率 = 的中レース数 / 母数、回収率 = 払戻合計 / 購入額合計。**母数となるのは結果が
確定したレース（1〜3 着が揃う。`isSettledResult`）かつ買い目が組めたレースのみ**で、
結果未着（当日進行中）・中止・不成立・返還のレースは分子（的中数・払戻）と分母
（母数・購入額）の両方から除外する。返還レースを「回収率 100%」として計上せず丸ごと
除外するのは、着順が出ず予想の当否を判定できないレースを母数に入れないため（購入額を
計上しない扱いは全額返還の会計上も整合する）。

### 穴予想の買い目 (v9_suji / v10_kimarite)

データソース: BoatraceCSV `estimate/suji` と `estimate/kimarite/picks`

穴予想 2 案は **buy list を CSV から読む**予想者。どちらも 5 点。

| | `v9_suji`(スジ予想、A案) | `v10_kimarite`(穴予想、B案) |
| --- | --- | --- |
| 1着 | 1 コース以外で強さpt 最大の艇(1 つに決まる) | 120 通りの確率の中で決まる(**5 点に複数の 1着艇が混ざる**) |
| 2-3着 | スジ表 `P(2着,3着 \| 1着)` の上位 5 ペア | 決まり手セル条件付きの表 × 強さpt 変調 |
| 強さpt | 1着の選定に直接使う | Stage2 の変調と Plackett-Luce とのブレンドに使う |

出目ごとに決まり手注釈(「まくり差し」等)が付く。注釈は**両案共通の静的テーブル**由来。
**レース単位の決まり手予測ではなく、出目 1 点ごとの説明**である点に注意
(BoatraceCSV `docs/design/ana_prediction.md` §14)。

> **2 案の優劣は回収率では決まらない。** 主判定は BoatraceCSV 側で月次集計する
> 3連単 log-loss(同 §13.3)。fun-site の回収率はガードレール。

### 利用していないデータ

オッズ・実測展示タイム・チルト角度・水面コンディションの詳細などは、現状の BoatraceCSV では取得できないか、本サイトでは使っていない。

## 2. 決まり手パターン

1 マーク（第 1 ターンマーク）の攻防でほぼ勝敗が決まる。

| 決まり手 | 説明 | 発生条件 |
|---|---|---|
| イン逃げ | 1 コースがそのまま先行して逃げ切り | 1 コースが A1 級、モーター好調、追い風 |
| 差し | 内側から 2〜3 コースが差す | 1 コースがターンで膨らんだ場合、2 コースの差し巧者 |
| まくり | 外側（主に 3〜4 コース）から一気にまくる | カド（4 コース）のスタートが早い、向かい風 |
| まくり差し | 外からまくりつつ内を差す | 高度な技術が必要、A1 級の実力者に多い |
| 抜き | 2 周目以降に逆転 | モーター性能差が大きい場合 |
| 恵まれ | 前の艇の失敗で繰り上がり | 転覆・落水・エンスト |

### スリット隊形

| 隊形 | 特徴 | よくある展開 |
|---|---|---|
| 横一線 | 全艇がほぼ同時にスリットを通過 | イン逃げ or 差し |
| 内凹み | インがスタート遅れ、外が出る | まくり or まくり差し |
| 外凹み | アウトがスタート遅れ | イン逃げ確率 UP |

### 艇番の色

公式の艇色対応。スタート予想 SVG・グラフの色分けに使用。

| 艇番 | 色 |
|---|---|
| 1 | 白 |
| 2 | 黒 |
| 3 | 赤 |
| 4 | 青 |
| 5 | 黄 |
| 6 | 緑 |

実装は [`packages/shared/src/constants/boat-colors.ts`](../packages/shared/src/constants/boat-colors.ts)。

## 3. 競艇場の特性

全 24 場のマスタは [`packages/shared/src/constants/stadiums.ts`](../packages/shared/src/constants/stadiums.ts)。

### イン天国（1 コース有利）

| 場 | 1 コース 1 着率の目安 | 特徴 |
|---|---|---|
| 大村 | ~65–70% | 全国 1 位。企画レースが多い |
| 徳山 | ~60% | コース広い、待機行動短い |
| 芦屋 | ~58% | サンライズV戦のイン勝率が高い |
| 下関 | ~57% | コース形状でイン有利 |

### 波乱場（穴狙い向き）

| 場 | 1 コース 1 着率の目安 | 特徴 |
|---|---|---|
| 戸田 | ~43% | 全国最狭水面（107.5m） |
| 江戸川 | ~44% | 唯一の河川コース、風と潮で大荒れ |
| 平和島 | ~45% | 風向・風速が不安定 |
| びわこ | ~47% | 高地で気圧低い、モーター出力↓ |

## 4. ページ表示上のフォールバック

直前情報や AI 評価の状態に応じて UI を切り替える。

| 状況 | 表示 |
|---|---|
| `previews/stt` 取得済み | 実測の進入コース・スタート展示を表示 |
| `previews/stt` 未取得 | 進入コース＝枠番で仮表示（ST はスタート予想図なら AI 推定 ST、racer_st も無ければ全国平均ST） |
| `estimate/index` `状態=daily` | 寄与pt から展示・気象を除外、3 要素のみ表示 |
| `estimate/index` `状態=realtime` | 5 要素すべて表示 |
| `results/realtime` 取得済み | レース詳細ページに結果セクションを表示 |
| `results/realtime` 未取得 | 結果セクションは非表示 |
| `results/payouts` 取得済み | レース詳細ページに「もし買ったら」セクション、トップに当日サマリーを表示 |
| `results/payouts` 未取得 | 両セクションともそのレースは集計から除外 |

**1 マーク走行距離**の予測 ST は既定で全国平均 ST。**`useEstimatedST` な予想者のみ**
(現行 active には該当なし。過去日の退役予想者ぶんでのみ効く) AI 推定 ST
(BoatraceCSV `estimate/racer_st`。実測 ST 履歴の時間減衰平均 + コース・F 補正)を
優先し、未生成時は全国平均 ST にフォールバックする
(`packages/shared/src/utils/one-mark-distance.ts` の `predictedST` / opt-in は
`PredictorSpec.useEstimatedST`)。走行距離は買い目の選定基準なので、ここは
回収率 A/B の対象になる。

一方**スタート予想図**の予測 ST は予想者に依らず AI 推定 ST(帯つき)で統一する。
図は表示専用で買い目・回収率に効かず、予測区間を持つのは AI 推定 ST 版だけのため
(BoatraceCSV `docs/design/slit_sim_plan.md` §9)。
買い目候補の選定は既定で 1 マーク走行距離基準(各着の基準艇 ±0.10)。
**`bettingStyle` が `"formation"` 以外の予想者(穴予想 v9_suji / v10_kimarite)は
fun-site で買い目を計算せず**、BoatraceCSV が出した出目をそのまま使う
(`bettingStyleFor(predictorId)` が読む CSV を決める)。
バッチが採点した買い目は `PredictorPrediction.dailyPicks` / `realtimePicks` に載り、
web はそれを描画する — 表示と集計が構造的に一致する。
**`strengthOnlyBetting` な予想者のみ**(現行 active には該当なし)、走行距離ではなく
**強さpt のみの ±5.0pt 窓**(距離式が強さpt/50 を項に持つため距離 ±0.10 と
等価スケール。ST 項を外した形)で候補を選定し、予測 ST は買い目に影響しない
(`computeBettingPicks` の `basis` 引数 / 解決は `bettingBasisFor(predictorId)`)。
予想者 ID から予測 ST の opt-in を解決するのは `oneMarkDistanceOptionsFor(predictorId)`、
選定基準・しきい値を解決するのは `bettingBasisFor(predictorId)` /
`bettingToleranceFor(predictorId)` で、
バッチの買い目生成(`prediction-builder.ts`)と web の買い目表示(`BettingPicks.astro`)は
**必ずこれらのヘルパー経由**で解決する。片側だけが渡し忘れると、
画面に表示される買い目と的中・回収率の集計対象になる買い目が食い違う。
全国平均ST が 0.00(公表実績なし。新人・長期離脱明け等)の艇は、スタート予想図の描画と
1 マーク走行距離計算の両方で `NO_RECORD_ST_FALLBACK`(0.25 秒)に補完する(`effectiveAvgST`)。
補完しない場合 0.00 が「最速スタート扱い」になるため。
